# Phiên 2.1: Đo đạc hiện trạng và chốt danh sách core plugin

> Ngày: 2026-10-16 · Trạng thái: **xong** · Giai đoạn: [2](2026-10-14-giai-doan-2-thu-gon-core-plugin.md) · Báo cáo số liệu: [docs/perf/2026-10-16-baseline.md](../perf/2026-10-16-baseline.md)

## Mục tiêu

Đo baseline (web + desktop), xếp hạng tính năng theo dung lượng mã, chốt danh sách core plugin cùng mặc định bật/tắt, đặt ngân sách hiệu năng cho Phiên 2.6. Không đổi hành vi app.

## Quyết định của chủ dự án

| Câu hỏi | Chọn |
|---|---|
| Đo web ở đâu | Cục bộ, bản build production (không bật staging, VPS đĩa ~90%) |
| Desktop đo tới đâu | Build Tauri thật (máy có Rust 1.95) |
| Mặc định bật/tắt | Giữ đề xuất gốc của file Giai đoạn 2 |
| Ngân sách | −30% JS tải đầu (web và desktop) với cấu hình mặc định; cây file không chậm hơn 10% |
| Tải lười KaTeX | Làm ngay ở Phiên 2.2 (cùng thí điểm Flashcards) |
| Việc ngoài plugin (ảnh thừa desktop, tải lười ngôn ngữ code, API trùng) | Chưa chọn; hỏi lại ở lô tương ứng |

## Đã làm

- `scripts/perf/bundle-report.mjs` (`npm run perf:web`, `npm run perf:desktop`): đọc đầu ra `next analyze --output` (định dạng `*.data`: 4 byte độ dài big-endian + JSON + phần nhị phân dạng CSR), tính **dung lượng riêng** của từng tính năng (số byte biến mất nếu bỏ tính năng, bằng đồ thị module), tách tải đầu và tải lười theo `chunk_groups` (Next 16.4), và đo JS tải đầu thật trên đĩa (gzip, brotli) từ `route-bundle-stats.json` (web) hoặc thẻ `<script>` của `out/index.html` (desktop).
- `scripts/perf/feature-map.json`: ánh xạ đường dẫn mã sang tính năng. Khi chuyển tính năng vào `packages/plugins` ở 2.2–2.5, thêm đường dẫn mới vào đây.
- `scripts/perf/seed-vault.mjs`: vault thử 500 note tất định, qua API hoặc ra thư mục; có `--cleanup`.
- Báo cáo baseline và ngân sách: `docs/perf/2026-10-16-baseline.md`.

## Phát hiện chính

- Tách plugin đơn thuần chỉ gỡ được tối đa **19%** JS tải đầu của web (327/1728 KB), trong đó KaTeX chiếm 257 KB. Mã ứng dụng của từng tính năng chỉ 5–35 KB.
- Mermaid (2,4 MB) và pdf.js (1,4 MB) đã tải lười sẵn.
- Ngân sách −30% gần như chắc chắn cần thêm tải lười bộ đọc cú pháp ngôn ngữ code (~150 KB thô).
- Mở vault web gọi `GET /vaults/:id` 3 lần, `preferences`/`workspace-state` 2 lần.
- Desktop nhúng ~6 MB ảnh/icon không dùng trên Windows.

## Bài học kỹ thuật

- Next 16 bỏ cột dung lượng khỏi `next build`. Dùng `next analyze --output` (16.4; ở 16.1 là `next experimental-analyze`). Analyzer **tự build riêng** nên tên chunk khác bản `next build`: phải đối chiếu theo nhóm chunk, không theo tên file.
- Analyzer của Next 16.1 không có `chunk_groups`. Trong `module_dependencies`, `import()` động vẫn nằm chung với import tĩnh, nên không suy được phần tải đầu từ đồ thị (đã thử: ra 6,9 MB thay vì 1,7 MB). Phần tải đầu thật của desktop lấy từ `out/index.html`.
- Web dùng Next 16.4.1 (`web/node_modules/next`), desktop dùng 16.1.6 (gốc `node_modules`).
- Trong Git Bash, đối số `"/"` bị đổi thành `C:\Program Files\Git`; desktop mặc định route `/` nên không cần truyền.
- Node trên Windows: `process.exit()` khi còn socket `fetch` mở gây assertion libuv; dùng `process.exitCode`.
- API cục bộ: đăng ký mặc định cần mã mời; chạy tiến trình với `REGISTRATION_MODE=open` (không sửa `.env`). Body đăng ký cần `acceptTerms: true`.
- Desktop portable (`portable.txt` cạnh exe) cách ly cả `config.json` lẫn dữ liệu WebView2, nên đo được mà không đụng `%APPDATA%\Noteriv` của chủ dự án.

## Chưa kiểm / giới hạn

- Thời gian cây file hiện và mở note trên **desktop** chưa đo (chỉ đo cửa sổ, lúc WebView bắt đầu dựng trang, và RAM).
- Đo web trên staging chưa làm (theo quyết định; để 2.6 nếu cần).
- Số thời gian đo trên máy cá nhân, API đi qua tunnel; chỉ so được với lần đo cùng điều kiện.
