## Đã làm

**Bốn core plugin** trong `packages/plugins/src/`. Mỗi plugin có view dạng lớp phủ và nhãn tiếng Việt (web) hoặc tiếng Anh (desktop):

- **`calendar`** (lịch và daily notes)
  - Lệnh "Mở lịch"; lệnh "Daily note hôm nay" phím `Mod+D`; hai nút ribbon.
  - Daily note vẫn là `Daily/YYYY-MM-DD.md`, tạo với `# ngày` nếu chưa có.
  - Lịch quét vault một lần mỗi lần mở (bản cũ quét lại mỗi khi đổi tháng, mỗi lần một request cho từng note).
- **`templates`**
  - "Tạo note từ template" (có nút ribbon) và "Chèn template": phím `Ctrl+T` trên desktop, `Ctrl+Alt+T` trên web (trình duyệt không cho trang chặn Ctrl+T).
  - Template là các note trong `Templates/`.
  - Tạo note ở gốc vault, **thêm hậu tố " 1", " 2" khi trùng tên** (trước đây web báo lỗi khi tạo lần hai).
- **`note-composer`**
  - Gộp: nối các note đã chọn vào note đang mở, có thể xoá note nguồn.
  - Tách theo H1/H2: **bỏ qua phần trùng tên file và báo lại**. Trước đây desktop ghi đè file đã có.
- **`vault-insights`**
  - Heatmap hoạt động, note kết nối nhiều và note mồ côi, tag, tăng trưởng, chuỗi daily note, sức khoẻ vault.
  - Phần tính toán thành hàm thuần dùng chung.
  - Note không có ngày thì bỏ khỏi biểu đồ và có ghi chú, thay vì hiện năm 1970.
  - Sửa lỗi desktop hiện tag thành `##tag`.

**Plugin API / host** (đặc tả: `docs/plugin-api/v1.md`, bảng "Thiếu sót phát hiện ở Lô A phần 1"):
- `vault.stats()` (ngày tạo/sửa theo đường dẫn) cùng `VaultAdapter.noteDates?()`: web lấy từ chỉ mục, desktop từ `getFileStats`. `PLUGIN_API_VERSION` 1.0.0-draft.3.
- Web: `createNote` tự tạo chuỗi thư mục còn thiếu.
- `onVaultChanged`: app làm mới cây file sau khi plugin ghi. `openPluginPath` của web tra lại qua adapter, nên mở được note vừa tạo (sửa luôn giới hạn đã ghi ở 2.2).
- Core plugin dùng được React: `react`/`react-dom` là peer dependency, helper `reactView`, test chạy trên jsdom.
- `useCorePluginHotkeys`: lệnh plugin chạy sau phím tắt của app nhưng vẫn trong cùng sự kiện, nên chặn được hành vi trình duyệt (Ctrl+D không mở hộp bookmark).
- `CorePluginViewOverlay`: gắn mỗi view vào một phần tử riêng. Sửa lỗi `removeChild` khi view React tự đóng từ handler click của nó.
- AppMenu (web): nhóm **"Plugin"** liệt kê lệnh của mọi core plugin đang bật.
- Ribbon (hai app): nút core plugin chuyển lên nhóm trên, vì đây là công cụ dùng hằng ngày.

**Gỡ mã cũ (hai app)**:
- `CalendarView`, `TemplatePicker`, `NoteComposer`, `VaultInsights` và các file lib tương ứng.
- `vault-insights.css`, cùng `templates.css` và `note-composer.css` của desktop. Đã đối chiếu: mọi selector đều có trong `packages/ui/styles/app.css`; khác biệt duy nhất là màu viết cứng thay cho biến theme.
- State và modal trong `page.tsx`, `handleDailyNote`/`handleCreateDailyNote`/`handleCreateFromTemplate`.
- Action `calendarView`, `dailyNote`, `insertTemplate`, `noteComposer`, `vaultInsights` trong `hotkeys.ts` và các bảng action.
- Mục AppMenu cũ, nút ribbon cũ, 5 icon không còn dùng.
- CSS của Insights chuyển vào `packages/ui/styles/app.css`.

## Kiểm chứng

- `npm run typecheck` sạch. `npm test`: 277 + 53 + 27 = **357 test đạt**. Test mới:
  - Phần thuần của bốn plugin (daily note, template, tên trùng, tách/gộp, insights có/không có ngày, chuỗi ngày).
  - Đăng ký lệnh, ribbon, view, phím tắt theo nền tảng.
  - Mount/unmount view React trên jsdom.
  - Host: `vault.stats`, `onVaultChanged`; phím plugin chạy sau listener của app và chặn hành vi mặc định.
- **Web chạy thật** (`next start` + API cục bộ, puppeteer):
  - Daily note trong vault **chưa có** thư mục `Daily`: tạo thư mục, tạo note, hiện trong cây, mở ra.
  - Lịch: chấm daily note, bấm đúp mở note.
  - Template tạo hai lần → `Meeting.md`, `Meeting 1.md`.
  - Ctrl+Alt+T chèn vào note đang mở.
  - Nhóm "Plugin" trong menu liệt kê đủ 7 lệnh.
  - Composer qua menu: tách tạo `Two.md`, bỏ qua `One.md` đã có và báo; gộp lưu đúng lên server (`## Two` và nội dung).
  - Insights có ngày (heatmap, tăng trưởng).
  - Ctrl+D mở daily note.
  - Không có lỗi trang; chỉ còn 404 của `favicon.ico`, có từ trước.
- **Desktop chạy thật** (`tauri build` portable, đường dẫn vault ghi bằng `/`, puppeteer qua cổng debug WebView2):
  - Ctrl+D tạo `Daily/<ngày>.md` trên đĩa.
  - Lịch tiếng Anh có chấm ở hôm nay.
  - Ctrl+T chèn template và lưu xuống đĩa.
  - Composer qua bảng lệnh: tạo `Two.md`, `One.md` còn nguyên.
  - Insights có ngày từ `getFileStats`.
  - Không có lỗi trang.

## Chưa kiểm / giới hạn

- Desktop, lần chạy **đầu tiên**: chèn template xong, script chuyển ngay sang note khác, và nội dung vừa chèn không được lưu xuống file. Lần chạy lại (chờ trước khi chuyển note) thì lưu trong vòng 10 giây. Chưa xác định được đây là do tự lưu của desktop khi đổi tab (có từ trước) hay do script. Nên thử tay: chèn template rồi đổi tab ngay.
- Tắt/bật từng plugin mới trong Cài đặt: cơ chế đã thử ở 2.2 (dùng chung), lần này chưa bấm lại cho từng plugin.
- Phím đã gán lại cho `dailyNote` / `insertTemplate` / `noteComposer` / `vaultInsights` / `calendarView` sẽ mất. Phím mặc định vẫn còn qua plugin (`Mod+D`, `Mod+T` trên desktop, `Mod+Alt+T` trên web).
- Desktop không có menu "Plugin" (menu desktop là menu gốc của hệ điều hành, `menu.rs`); vào bằng ribbon và bảng lệnh.

## Bài học

- Live preview ẩn dấu `##` ở dòng heading không có con trỏ: kiểm nội dung bằng API hoặc file, không đọc chữ hiển thị.
- Script thử: bấm vào thư mục đang mở sẽ **thu** thư mục lại; tên note trùng với chữ trên nút (ví dụ "Split") làm bấm nhầm. Nên chọn theo selector.
- View React của plugin tự đóng từ handler click của nó: phải hoãn `root.unmount()`, và host không được xoá DOM bên trong trước khi React gỡ xong.
