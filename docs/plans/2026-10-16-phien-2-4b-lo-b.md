# Phiên 2.4b: Lô B (phần 2): Board và view theo loại file

> Ngày: 2026-10-16 · Trạng thái: **xong** (chưa push) · Giai đoạn: [2](2026-10-14-giai-doan-2-thu-gon-core-plugin.md) · Phần 1: [Phiên 2.4](2026-10-16-phien-2-4-lo-b.md)

Không có câu hỏi mới cho chủ dự án. Hai quyết định đã chốt từ trước:
- Chia Lô B thành 2.4 và 2.4b.
- Board mặc định **tắt** (chốt ở 2.1). Khi tắt, file board mở như markdown thường; dữ liệu không đổi.

## Đã làm

**Cơ chế mới: view theo loại file** (`PLUGIN_API_VERSION` 1.0.0-draft.6; đặc tả: `docs/plugin-api/v1.md`):

- **API**: `ui.registerFileView({ id, match, mount })`.
  - `mount(container, ctx)` nhận `ctx.path`, `ctx.content` và `ctx.setContent(...)`.
  - Nó trả về `{ update?, destroy? }`.
- **Host** (`packages/ui/src/plugins/`):
  - Thêm đóng góp `fileViews` (có `guard` quanh `match`) và `host.findFileView`.
  - Thêm component `CorePluginFileView` và helper `matchFileView`.
  - Mỗi pane mount một phiên bản. `setContent` đi vào handler nội dung thường của pane. Nội dung đổi từ nơi khác tới view qua `update`; host không gửi lại chính nội dung view vừa ghi.
- **Hai app**:
  - Dispatch của note hỏi plugin trước: web dùng `renderNoteBody`, desktop dùng pane chính và split pane. Chế độ source luôn là editor thô.
  - Desktop ẩn FormattingToolbar khi có view khớp.
  - Vòng tự lưu 5 giây của desktop (trước chỉ cho board) nay áp cho mọi tab đang hiện view theo loại file.

**Plugin `board`** (`packages/plugins/src/board/`):

- File view nhận `*.board.md` **hoặc** frontmatter `board: true` trên cả hai app. Trước đây web chỉ nhận frontmatter và hiện board cả ở chế độ source.
- `BoardView` chuyển nguyên vào plugin. Hai bản cũ giống hệt nhau, toàn style inline.
- Lệnh tạo board mới ("Board: tạo board mới" / "New board"): tạo `Board.board.md` hoặc `Board N.board.md` ở gốc vault rồi mở. **Web có lệnh này lần đầu.**

**Gỡ mã cũ:**

- `web|desktop/src/components/BoardView.tsx`.
- Các nhánh board trong dispatch.
- Desktop: `handleNewBoard` và action `newBoard`.

## Kiểm chứng

- `npm run typecheck` sạch. `npm test`: 280 + 62 + 44 = **386 test đạt**. Test mới:
  - Board:
    - Nhận theo tên và frontmatter.
    - Lệnh tạo board chọn tên chưa dùng.
    - View vẽ cột; tick thẻ thì ghi qua `setContent`; `update` vẽ lại; `destroy` dọn sạch.
  - Host:
    - `findFileView` theo thứ tự đăng ký; `match` ném lỗi coi như không khớp; tắt plugin thì hết khớp.
    - `CorePluginFileView` không gửi lại nội dung view vừa ghi, gửi thay đổi từ nơi khác qua `update`, dựng lại khi đổi file và dọn khi unmount.
- **Web chạy thật** (puppeteer, `next start` và API cục bộ):
  - `Plans.board.md` không có frontmatter hiện thành board.
  - Thêm thẻ thì máy chủ lưu.
  - Chế độ Source hiện markdown. Thêm một dòng `- [ ] gamma` ở đó rồi quay về Edit thì board có thẻ mới.
  - Note có frontmatter `board: true` trong thư mục con hiện thành board.
  - Lệnh "Board: tạo" trong bảng lệnh tạo `Board.board.md` và mở ra thành board.
  - Tắt plugin thì file mở như markdown.
  - Không có lỗi trang.
- **Desktop chạy thật** (Tauri portable, cổng debug WebView2):
  - Board hiện, không có FormattingToolbar.
  - Thêm thẻ thì file trên đĩa được ghi sau **5,1 giây** (vòng 5 giây, không phải 30 giây).
  - "Split Editor" hiện hai board độc lập.
  - Source hiện markdown.
  - "New board" tạo file trên đĩa và mở thành board.
  - Không có lỗi trang.

## Chưa kiểm / giới hạn

- Chữ trên giao diện Board vẫn là tiếng Anh trên web ("+ Add card"…), như bản cũ. Chưa dịch.
- Collab web trên một board: `setContent` đi qua `onDraftChange` như khi gõ (có đẩy lên Yjs), nhưng chưa thử hai người cùng sửa.
- `match` của view theo loại file hiện chỉ áp cho **note markdown**. Canvas/Drawing/PDF (Lô C) là file khác loại, và trên desktop mở theo `kind` của tab ngoài luồng note. Lô C cần mở rộng cơ chế này (ghi trong đặc tả).
