# Noteriv Plugin API v1 (bản nháp, `0.x`)

> **Chưa đóng băng.** Có thể đổi giữa các phiên của Giai đoạn 1–3. Nguồn kiểu duy nhất: `packages/plugin-api/src/index.ts` (`@noteriv/plugin-api`). File này giải thích ý đồ; khi hai nơi lệch nhau, kiểu TypeScript thắng.

## 1. Hai tầng, một bề mặt

| | Core plugin | Plugin cộng đồng |
|---|---|---|
| Ai viết | Dự án (tin cậy) | Bất kỳ ai |
| Nằm ở | `packages/plugins/<tên>/` trong repo | Thư mục plugin của vault (web: DB; desktop: `.noteriv/plugins/<id>/`) |
| Chạy | Trong ứng dụng, nạp bằng `import()` động, có DOM thật | Iframe `sandbox="allow-scripts"` (nguồn gốc mờ), mọi lời gọi là RPC postMessage |
| Quyền | Không cần xin | Mặc định chặn; người dùng cấp (`PluginPermission`) |
| Bật/tắt | Settings → Core plugins | Plugin Manager |

Cả hai nhận cùng một đối tượng `PluginApi`: `vault`, `editor`, `markdown`, `ui`, `events`, `workspace`, `settings`, `app`.

## 2. Vòng đời

- **Core plugin:** module ES có `export default { onload(api), onunload?() }` (`CorePlugin`). Bật: host `import()` module rồi gọi `onload(api)`. Tắt: gọi `onunload`, rồi host **tự gỡ mọi thứ plugin đã đăng ký qua `api`** (lệnh, status bar, ribbon, view, code block, sự kiện, panel). Plugin không phải tự dọn, và một plugin lỗi `onunload` cũng không để lại rác. Tắt plugin thì mã của nó không nằm trong bundle ban đầu.
- **Plugin cộng đồng:** script gán `module.exports = { onLoad(api), onUnload() }` (giữ nguyên tên và dạng của v0, nên plugin cũ như `chessboard` chạy tiếp).

### Tập con của sandbox

Plugin cộng đồng không có DOM thật của ứng dụng, nên ở tầng đó: mọi hàm ghi "core" trong bảng trên (`registerView`, `addRibbonIcon`, `addNoteToolbarButton`, `registerPostProcessor`, `renderReadOnly`, `openView`, `closeView`, `vault.stats`, `saveAttachment`, các hàm lịch sử note…) **không có** (gọi sẽ báo lỗi rõ ràng). Panel và tab cài đặt dùng cơ chế phản chiếu HTML (Shadow DOM, đã lọc) như bản web hiện tại.

## 4. Cấp quyền (tầng cộng đồng)

- Manifest có thể khai `permissions`. Nếu không, host **suy ra đề xuất** từ mã (`inferPermissions` trong `@noteriv/core/permissions`: chỉ tính lời gọi `api.<ns>.<method>`), hiện cho người dùng xem và xác nhận. Suy ra chỉ là đề xuất: quyền thật luôn được kiểm lúc chạy, thiếu quyền thì lời gọi bị từ chối và Plugin Manager hiện nút cấp.
- Đổi quyền thì iframe được dựng lại.

## 5. Đăng ký và lưu trạng thái

`PluginRegistry` (`@noteriv/core/plugin-registry`) giữ danh sách core plugin (`id`, `name`, `description`, `defaultEnabled`, `load()`), đọc/ghi trạng thái bật/tắt qua `PluginStateStore`:

- Web: `vault.settings.corePlugins` (DB, qua `VaultAdapter.getSettings/saveSettings`).
- Desktop: khoá `core` trong `.noteriv/plugin-config.json`.

Chưa có mục nào trong trạng thái → dùng `defaultEnabled`.

## 6. Tính tương thích

- Plugin cộng đồng v0 (`api.vault/ui/events/editor/markdown/app`) chạy không đổi trên cả hai nền tảng qua sandbox.
- Quy tắc id: id lệnh/status/panel là cục bộ trong plugin; host thêm tiền tố `<pluginId>:`.

## 7. Cài đặt hiện tại (Phiên 1.5, cập nhật 2.2)

| Phần | Nơi |
|---|---|
| Kiểu | `packages/plugin-api/src/index.ts` |
| Đăng ký, vòng đời, quyền suy ra | `packages/core/src/plugin-registry.ts`, `permissions.ts` |
| Host core | `packages/ui/src/plugins/` (`createCorePluginHost`, `useCorePluginHost`, `useCorePlugins`, `useCorePluginHotkeys`, `CorePluginsSection`, `CorePluginViewOverlay`) |
| Host sandbox | `packages/ui/src/plugins/sandbox/` (`useSandboxPluginHost`, `PluginMirror`) + `packages/ui/public/plugin-sandbox.html` (sao chép vào `public/` của mỗi app: `npm run sync:sandbox`) |
| Core plugin | `packages/plugins/src/<id>/index.ts` (hiện có `word-count`, `flashcards`, `calendar`, `templates`, `note-composer`, `vault-insights`, `markdown-lint`, `audio-recorder`, `graph`, `slides`, `note-history`, `board`; phần dùng chung ở `src/shared/`); mỗi app khai danh sách ở `src/lib/core-plugins.ts` với `load: () => import("@noteriv/plugins/<id>")` |

Ghi chú hành vi:

- `vault.list(dir)` trả **con trực tiếp** của `dir` (tệp và thư mục, thư mục trước). `vault.*` chỉ thấy ghi chú markdown (đi qua `VaultAdapter`).
- `vault.write` tạo note mới **cùng các thư mục còn thiếu** trên cả hai nền tảng (từ 2.3; trước đó web báo lỗi khi thư mục chưa có). Sau `write`/`delete`, host báo app làm mới cây file (`onVaultChanged`), và `workspace.openFile` trên web tìm được note vừa tạo.
- `vault.stats()` (từ 2.3): `{ [đường dẫn]: { createdAt, modifiedAt } }` (ms). Web lấy từ chỉ mục, desktop từ `getFileStats` (một lời gọi); note thiếu ngày thì không có trong kết quả.
- **Phím tắt của plugin** chạy sau mọi phím tắt của app nhưng vẫn trong cùng sự kiện, nên chặn được hành vi của trình duyệt (Ctrl+D không mở hộp bookmark). Ctrl+T và Ctrl+Shift+T thì trình duyệt không cho trang chặn: lệnh web dùng phím khác.
- **Core plugin được dùng React** (từ 2.3): `react`/`react-dom` là peer dependency của `@noteriv/plugins`, dùng chung bản của app. Helper `reactView(render)` trong `packages/plugins/src/shared/react-view.ts` biến một component thành `ViewFactory`; unmount được hoãn một tick vì view thường tự đóng từ trong handler sự kiện của nó. API vẫn không phụ thuộc framework (Flashcards dùng DOM thuần).
- `vault.read/exists/list` dùng chung **một danh sách note trong 2 giây** (từ 2.2): plugin quét cả vault không gây hàng trăm lần tải chỉ mục trên web. `write`/`delete` qua API xoá bộ đệm; thay đổi từ nơi khác hiện ra sau khi bộ đệm hết hạn.
- Phím tắt của lệnh plugin không bao giờ lấn phím tắt của app: listener của app gọi `preventDefault` (hoặc dừng sự kiện) thì plugin bỏ qua. **Keymap riêng của editor không tính là app** (từ 2.4): CodeMirror có `Mod-g`, `Mod-d`…; host nhận phím của plugin ngay ở giai đoạn capture nên editor không xử lý nữa (trước 2.4, Ctrl+G/Ctrl+D không chạy khi con trỏ ở trong editor).
- **View** (từ 2.2): `workspace.openView` hiện view dưới dạng **lớp phủ** giữa màn hình (`CorePluginViewOverlay`, một view mỗi lúc); Esc, bấm ra ngoài hoặc `workspace.closeView()` thì đóng và gọi hàm dọn mà `mount` trả về. Tắt plugin cũng đóng view của nó. Sau này có thể đổi sang tab mà không đổi API.
- `registerPostProcessor` đã được host lưu nhưng renderer **chưa gọi**; sẽ nối khi Giai đoạn 2 cần.
- **Chuyển dữ liệu cũ của một tính năng thành plugin** (mẫu dùng ở Flashcards, 2.2): `loadPluginSettings` của app trả `{ legacy… }` lấy từ chỗ lưu cũ khi plugin chưa lưu lần nào; plugin chuyển đổi, lưu ngay qua `settings.save` (từ đó app không đưa dữ liệu cũ nữa). Chỗ lưu cũ không bị ghi hay xoá, giữ làm bản sao lưu.

- **Panel bên của core plugin** (từ 2.3b): `ui.addSidebarPanel` hiện ở **cột phải** cạnh Outline/Backlinks (`CorePluginSidePanels`), mỗi panel có nút ribbon tự sinh để bật/tắt; plugin tự bật/tắt bằng `ui.toggleSidebarPanel(id)`. Tắt plugin thì panel biến mất. (Panel của plugin cộng đồng trên web vẫn thay cây file bên trái như trước.) Tab cài đặt của core plugin **chưa** được hiển thị (chưa plugin nào cần).
- `editor.setCursor({ line, ch })` (từ 2.3b): 0-based như `getCursorPosition`, tự chặn số dòng ngoài phạm vi, cuộn tới và focus editor.
- **Nút trên thanh công cụ note** (từ 2.4): `ui.addNoteToolbarButton({ id, title, icon, onClick })`; `icon` là chuỗi `<svg>` hoặc chữ ngắn. Web vẽ trong `NoteToolbar` (`CorePluginNoteToolbarButtons`). **Desktop không có thanh công cụ note nên không hiện**: plugin luôn có lệnh (và nếu cần, nút ribbon) cho cùng hành động.
- **View theo loại file** (từ 2.4b): `ui.registerFileView({ id, match({ path, content }), mount(container, ctx) })`. App hỏi `match` (giữ rẻ: gọi mỗi lần vẽ tab) khi vẽ một tab; view đầu tiên khớp (theo thứ tự đăng ký; `match` ném lỗi coi như không khớp) **thay editor ngay trong tab**, ở cả pane chính lẫn split pane, mỗi pane một phiên bản (`CorePluginFileView`, `matchFileView`). `ctx.setContent` ghi vào bộ đệm của tab như khi gõ: dấu chưa lưu, lưu, tự lưu, collab trên web. Nội dung đổi từ nơi khác (sửa ở chế độ source, file đổi trên đĩa, collab) tới view qua `update`; host không gửi lại chính nội dung view vừa ghi. Chế độ **source** luôn hiện editor thô. Desktop tự lưu các tab đang hiện view theo loại file mỗi 5 giây (editor thường là 30 giây), vì thao tác trên view là thao tác rời (kéo thẻ) chứ không phải gõ. Tắt plugin thì các tab trở về editor.
- **Lịch sử note** (từ 2.4): `vault.versionSources()` cho biết vault có bản lưu tự động (snapshot) và lịch sử git không; `snapshots(path)` / `gitLog(path)` trả danh sách mới nhất trước, `readSnapshot` / `readAtCommit` trả nội dung (`null` nếu không đọc được). Thiếu nguồn thì danh sách rỗng, không báo lỗi. Web: snapshot do job máy chủ tạo khoảng 10 phút một lần; git chỉ có khi vault có kết nối đồng bộ git đã chạy. Desktop: snapshot trong `.noteriv/snapshots` (mỗi lần lưu, id là tên file, chỉ đọc được snapshot của chính note đó); git của thư mục vault. Qua các method tuỳ chọn `VaultAdapter.historySources/noteSnapshots/readNoteSnapshot/noteGitLog/readNoteAtCommit`. Việc **ghi** snapshot vẫn thuộc app (File Recovery là tính năng lõi).
- `markdown.renderReadOnly(source, el)` (từ 2.4): vẽ markdown chỉ đọc bằng chính live preview của editor (`ReadOnlyView`, tải khi dùng lần đầu, có thể vẽ bất đồng bộ); trả hàm dọn. App không cung cấp thì host hiện chữ thô.
- `vault.saveAttachment(name, blob)` (từ 2.3b): trả về đích cho link markdown. Web: tải lên kho đính kèm, trả URL tải về. Desktop: ghi **nhị phân** vào `attachments/<name>`, trả `attachments/<name>`. Host làm sạch tên: các ký tự `/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|` thành `_`, bỏ dấu chấm ở đầu tên.

## 8. Chưa có / sẽ tới
